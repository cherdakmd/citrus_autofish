# Citrus AutoFish для Horizon

Авто-рыбалка для **Horizon** — реализации Minecraft: Java Edition 26.3, переписанной на Rust. Это native-мод Horizon, а не Fabric/Forge-мод, не Bedrock-addon и не игра Rust.

> **v0.1.6 — экспериментальный исходный релиз.** Native-build успешно завершился у пользователя на Windows PowerShell 5.1 / Horizon Launcher 0.2.69 для Horizon revision `9f42064` (2 мин 27 с, Performance); лаунчер сообщил, что билд установлен и выбран для инстанса. Игровой тест авто-рыбалки ещё не подтверждён.

## Как работает

- `/autofish` включает или выключает режим; по умолчанию он выключен.
- Серверный native hook замечает поклёвку. После этого мод отправляет серверу обычный `UseItem` play packet для вытягивания удочки и, после задержки в 4 тика, для следующего заброса.
- Это **экспериментальная замена** штатному нажатию `key.use`: Horizon из сборки Launcher 0.2.69 не предоставляет очередь `click_mapping`. Пакет собирается через `ServerboundPlayPacket::decode` (packet id 67 из закреплённой ревизии 9f42064), без прямого доступа к `horizon-protocol`.
- Пакет использует отдельный счётчик sequence мода, поскольку старый API не предоставляет текущий sequence клиента. Он не синхронизирован с действиями игрока; одновременное использование предметов/блоков может привести к конфликтам подтверждений. Отключите мод при обычной игре, если замечаете проблемы.
- В этой сборке команда не выводит подтверждение в чат. Повторно введите `/autofish`, чтобы переключить состояние.

Сценарий требует, чтобы удочка была выбрана и была связь с серверной частью Horizon. На удалённом vanilla-сервере нужный серверный hook может не сработать. Считать работу на одиночном мире подтверждённой пока нельзя.

## Установка через Horizon Launcher 0.2.69 (Windows)

1. Скачайте и распакуйте исходный ZIP релиза `v0.1.6`.
2. В PowerShell перейдите в распакованную папку проекта — ту, где находится этот `README.md`.
3. Запустите native build, передав лаунчеру **папку мода**, а не корень репозитория:

   ```powershell
   & "C:\Users\ADMIN\AppData\Local\Programs\Horizon Launcher\horizon-launcher.exe" native-build .\mixins\citrus_autofish --trust-native-code
   ```

   Если лаунчер установлен в другом месте, укажите его фактический путь. Оставьте `&`, кавычки и путь `mixins\citrus_autofish`.

4. Если сборка прошла успешно, запустите инстанс Horizon, войдите в мир и введите `/autofish`.
5. Проверьте сначала на тестовом мире. При ошибке сборки сохраните полный текст вывода; при проблемах с игровыми действиями выключите мод и сообщите, что именно произошло.

Для Bash/Linux/macOS команда из корня проекта:

```sh
horizon-launcher native-build ./mixins/citrus_autofish --trust-native-code
```

## Совместимость

- Minecraft: Java Edition 26.3.
- Horizon Launcher 0.2.69.
- Исходная ревизия Horizon закреплена на `9f42064c11efe7ef3e5ed2baad7ddc2a3b36eea0`.
- Дополнительной зависимости на `horizon-protocol` нет: пакет `UseItem` декодируется через публичный `ServerboundPlayPacket::decode` из зафиксированного Horizon API. Это избегает запрещённой bundle-path зависимости.
- `95c79d7` намеренно не используется: в ней отсутствует `crates/horizon-mods/Cargo.toml`, требуемый staging workspace Launcher 0.2.69. Этот несовместимый pin вызвал ошибку сборки v0.1.1.

## Безопасность

Native-мод — исполняемый Rust-код с правами пользователя, а не песочница. `--trust-native-code` разрешает лаунчеру собрать и запустить его. Сборка не содержит бинарного файла: лаунчер собирает исходники локально. Перед подтверждением проверяйте код.

## Структура

- `mixins/citrus_autofish/horizon-mixin.toml` — manifest native bundle для CLI 0.2.69.
- `mixins/citrus_autofish/engine/Cargo.toml` — зависимости и pin Horizon.
- `mixins/citrus_autofish/engine/src/lib.rs` — native hooks, toggle и экспериментальная отправка `UseItem` пакетов.
- `compatibility.json` — зафиксированные версии.
